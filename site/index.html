A web crawler that maps a site as a graph, not a list.

Every page, script, image and external host becomes a node, and every link between them an edge. Each crawl is saved, so you can query it later and diff it against the last one.

why a graph

Most crawlers hand you a list of URLs. Useful for the next tool in the pipe, useless a day later. ReconGraph keeps the structure: what links to what, what is only reachable from a script, and what changed since your last crawl.

Orphans

Pages and endpoints that nothing links to, found through sitemaps, scripts and form actions.

Reachability

How many clicks a path is from the front door, and which edges get you there.

Third parties

Every external host the site references, counted by how many nodes point at it.

query

Ask the saved graph, not the site.

Queries read the stored crawl, so nothing is fetched again. latest can be any crawl ID, a prefix of one, or latest~1.

Find what nothing links to

Nodes that no anchor points at, and the kind of edge that led the crawler to them.

recongraph query latest --orphans
3 node(s) with no inbound anchor:

  https://example.com/api/v1/users
      status 404, kind page, reachable via js-endpoint
  https://example.com/from-sitemap.html
      status 200, kind page, reachable via nothing (listed in a sitemap)
  https://example.com/search
      status 404, kind page, reachable via form-action

How far it is from the front door

Shortest path from a seed URL to any node in the graph.

recongraph query latest --path-to /blog/post-1.html

  * https://example.com/
     `-> https://example.com/blog/

Hosts outside the target, recorded as nodes but never fetched.

faq

Before you point it at something

What doesn't it do?

It doesn't render JavaScript. There's no headless browser, so a single-page app that builds its DOM at runtime comes back as a handful of nodes. Use katana for those. Scripts are tokenised, not executed: it finds URLs passed to fetch(), axios and xhr.open, and API-shaped strings. String constants are folded in, so const base = "/api"; fetch(base + "/users") resolves to /api/users; anything still assembled at runtime is reported as a partial like /api/users/{}.

How hard does it hit a site?

Not hard. It respects robots.txt, sends 2 requests a second per host with a burst of 4, and halves that rate for the rest of the crawl if a host answers 429 or 503. External hosts are recorded as nodes but never fetched. --rate and -c change the pace; --ignore-robots exists for authorised work and prints a warning.

Where do crawls go?

One gzipped JSON file per crawl in ~/.recongraph/crawls, readable with gunzip -c … | jq. Nothing leaves your machine. recongraph list shows them, and any two can be diffed.

Can I get the graph out?

Yes: -f json, adjacency, dot, csv, or html for a self-contained interactive view. svg works if Graphviz is installed.

Does it still work in a pipeline?

The default output is one URL per line, and it reads seed URLs from stdin, so cat hosts.txt | recongraph crawl | httpx works. The graph is saved alongside.
